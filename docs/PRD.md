# Oasis Documents — 产品需求文档（v2）

## 项目定位

个人数字资产管理中枢：把散落在本地文件夹、各平台收藏、订阅源里的内容，**整理到一处、检索一处、阅读一处**。

四大目标（同等权重，缺一不可）：

1. 电脑里的文件**快速整理**
2. **快速检索**：以图搜图、以文搜图、以文搜文
3. **三方平台内容**（小红书、抖音、微信、CSDN 等）的集成检索
4. 自己账号**订阅内容的集成查看**

---

## 一、快速整理（目标 ①）

### 用户故事
> "我的下载文件夹里有 2000 个文件，截图、PDF、安装包、临时文档混在一起。我不记得哪些重要、哪些重复。我想要一个按钮，帮我把乱麻变成整齐的文件夹结构，且绝不弄丢任何东西。"

### 核心功能

**1.1 全盘扫描与盘点**
- 扫描指定目录（默认 Downloads / Desktop / Documents，用户可增删）
- 按类型聚类展示：图片、文档、视频、音频、压缩包、安装包、代码、其他
- 识别"垃圾"：重复文件、零字节文件、超过 N 月未访问的安装包/临时文件

**1.2 重复文件检测（双层）**
- **精确重复**：SHA-256 哈希相同 → 100% 重复
- **近似重复（图片）**：感知哈希（pHash/dHash，sharp 可算）→ 缩略图、连拍、不同尺寸版本
- 检测结果按"重复组"展示，每组内标记推荐保留的版本（分辨率最高/最新），其余可勾选清理

**1.3 智能分类建议（不自动移动！）**
- 基于内容理解打标签：OCR 文字、文件名语义、目录上下文
- 规则引擎（声明式 YAML，用户可编辑）：
  ```yaml
  rules:
    - name: 截图归档
      when: { path: "~/Desktop", mime: "image/*", name_matches: "屏幕快照|Screenshot" }
      suggest: "~/Documents/截图/{YYYY}/{MM}"
    - name: 安装包清理
      when: { mime: "application/x-dmg", last_accessed_before: "6个月前" }
      suggest: "trash"
  ```
- **安全底线**：只给建议 + 用户确认后执行；所有移动操作记录日志，支持撤销；移动采用复制-校验-删除顺序

**1.4 一键归档**
- 用户确认建议后批量执行移动/重命名
- 执行报告：移动了什么、跳过了什么、失败原因
- Finder/访达中反映真实文件系统变化（不是虚拟视图，避免双份真相）

### 交互设计
- 主视图为「整理工作台」：左侧类型树 + 重复组，右侧文件预览
- 建议以卡片形式呈现："发现 47 个重复截图，可释放 230MB → [查看] [一键清理]"
- 首次打开应用引导添加监控目录

## 二、快速检索（目标 ②）

### 用户故事
> "我记得上周看过一张架构图，但忘了存在哪。"/"我记得某篇公众号文章讲过这个技术点。"

### 核心功能

**2.1 三种检索方式**
| 方式 | 输入 | 背后逻辑 |
|---|---|---|
| 以文搜文 | 文本查询 | 查询文本嵌入 → 文档/网页/OCR 文本向量集合检索 |
| 以文搜图 | 文本查询 | 查询文本经 CLIP 文本编码器 → 图片向量集合检索 |
| 以图搜图 | 拖入/粘贴图片 | 图片经 CLIP 图片编码器 → 图片向量集合检索 |

**2.2 统一搜索框（⌘K）**
- 一个入口，结果分标签页：全部 / 图片 / 文档 / 网页收藏 / 笔记
- 混合排序：语义相关性 + 关键词命中 + 时间衰减
- 图片结果以缩略图网格展示，文档结果以标题+摘要展示，命中片段高亮

**2.3 索引内容**
- 图片：CLIP 向量 + OCR 文字 + EXIF（拍摄时间、地点）
- 文档（PDF/Word/Markdown/txt）：全文提取，段落切片嵌入
- 网页收藏/平台内容：标题 + 正文 + 作者 + 标签
- 索引状态可视化：进度条、失败项列表、可重试

**2.4 嵌入引擎（本地 + 在线双模式）**
- 默认本地：CLIP + BGE-small-zh ONNX（CPU 可跑，~400MB，完全离线）
- 可选在线：OpenAI / 智谱 / 通义等嵌入 API，设置页配置（详见 ARCHITECTURE.md）
- 图片向量始终由本地 CLIP 生成（在线 API 不支持图片），文本向量随所选模式
- 切换模型时提供重新索引选项，后台增量执行

## 三、三方平台内容集成（目标 ③）

### 用户故事
> "我在小红书收藏了装修攻略，在抖音收藏了教程，微信公众号收藏了技术文章，CSDN 收藏了解决方案。想用时根本想不起在哪个平台，更找不到。"

### 核心功能

**3.1 三级接入策略（按实现成本递进）**

| 级别 | 方式 | 说明 |
|---|---|---|
| L1 | **分享链接导入** | 粘贴小红书/抖音/公众号/CSDN 分享链接 → 解析出标题、正文、图片 → 入库索引。无登录态要求，最稳 |
| L2 | **批量导入** | 各平台收藏夹手动导出（HTML/书签/收藏集）→ 解析入库 |
| L3 | **自动同步** | 内嵌浏览器窗口（Electron BrowserView）登录平台 → 定期拉取收藏列表。**有封号风险，明确警示用户，默认关闭** |

**3.2 统一内容模型**
所有平台内容归一化：
```
{ title, content, url, author, platform, tags[], mediaUrls[],
  collectedAt, contentType: 'note'|'video'|'article' }
```
媒体（图片/视频封面）下载到本地 media 目录，正文提取为纯文本 + 保留原链接跳转。

**3.3 平台接入设计（插件化）**

```typescript
interface PlatformPlugin {
  id: 'xiaohongshu' | 'douyin' | 'wechat' | 'csdn' | ...
  /** 解析分享链接 → 统一内容模型 */
  parseShareLink(url: string): Promise<PlatformContent>
  /** 解析导出文件（HTML/JSON） */
  parseExportFile(path: string): Promise<PlatformContent[]>
  /** [L3] 拉取收藏（需登录态） */
  fetchBookmarks?(auth: AuthState): AsyncGenerator<PlatformContent>
}
```

各平台现实约束与对策：

| 平台 | 现实约束 | 对策 |
|---|---|---|
| 小红书 | 无公开 API，Web 端校验严格 | L1 优先：分享文本中的短链 → 服务端渲染页解析；L3 用内嵌窗口 |
| 抖音 | 分享链接有时效性 | 短链解析 + 立即抓取媒体；视频本体不下载（版权），存封面+简介+链接 |
| 微信公众号 | 文章在微信内打开，外部 UA 可能被拒 | 公众号文章链接大部分可直接抓取（mp.weixin.qq.com）；收藏导出走 L2 |
| CSDN | 有开放结构，反爬弱 | L1/L2 均可行，正文直接抓取 |
| 知乎/B站 | 各有收藏 API/导出 | P2 之后再接 |

**3.4 集成检索**
- 平台内容与本地文件在同一个搜索框检索
- 结果卡片带平台标识（图标 + 配色），点击跳转原文（或打开本地缓存正文）
- 支持按平台过滤

## 四、订阅内容集成查看（目标 ④）

### 用户故事
> "我订阅了十几个公众号、几个 RSS 博客、一些 B 站 UP 主。每天要挨个打开看，太散了。"

### 核心功能

**4.1 订阅源管理**
- RSS/Atom：添加 URL，自动发现（输入站点域名自动找 feed）
- 微信公众号：通过 RSSHub 等桥接服务订阅（用户自建或公共实例）
- CSDN/知乎/B站关注：L3 自动同步或定期检查
- Newsletter（P2）：绑定邮箱 IMAP，按发件人规则归档

**4.2 统一时间线**
- 所有订阅源合并为单一时间线，按发布时间排序
- 过滤器：按源 / 按平台 / 已读未读 / 收藏星标
- 未读计数侧栏展示

**4.3 阅读体验**
- 正文提取（去广告/导航/评论），纯净阅读视图
- 阅读进度记忆、已读状态同步
- 划线高亮 + 笔记（存入本地 SQLite）
- 一键收藏到「我的内容库」（与目标①②③打通：收藏即入库、入库即可检索）

**4.4 订阅内容也进检索**
- 时间线文章自动提取正文并嵌入索引
- 搜索结果中订阅文章与本地文件、平台收藏同列

- [ ] 整理规则引擎（YAML 规则 + 建议卡片 + 确认执行 + 撤销日志）
- [ ] 图片索引：CLIP 向量 + OCR + EXIF；文档索引：全文切片 + BGE 嵌入

## 八、关键设计决策

| 决策 | 理由 |
|---|---|
| 整理只建议、不擅动 | 文件安全第一：所有移动经用户确认，可撤销，日志留痕 |
| 真实文件系统，非虚拟库 | 避免双份真相；用户在 Finder 里看到的就是应用整理的结果 |
| 平台接入 L1→L2→L3 递进 | 分享链接解析成本最低最稳；自动同步有封号风险，默认关闭 |
| 图片向量永远本地 CLIP | 在线嵌入 API 不支持图片；本地 CLIP 是图搜图/文搜图的基础设施 |
| 视频本体不下载 | 版权与存储考虑，存封面+简介+外链 |
| 订阅内容也进索引 | 四大模块最终汇聚到同一个检索入口 |
